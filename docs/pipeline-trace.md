## 1. Client Polling Hook & Notification Transition Logic

### Source Location
- [`TicketTable.tsx`](file:///A:/TrainSolo/train-ticket-tracker-client/src/pages/TicketTable/TicketTable.tsx)

### Polling Engine & Cadence
- **Authoritative Cadence**: `30,000 ms` (30 seconds), established by `setInterval(fetchAllTickets, 30000)` at line 128.
- **Request Cycle**:
  1. On each tick, maps across all configured routes (`scans` in `TicketContext`).
  2. Constructs route key: `${scan.from}-${scan.to}-${formatDate}`.
  3. Issues `POST /tickets` with `{ from, to, date }` via `axiosInstance`.
  4. Interceptor automatically attaches credentials (`token`, `ssdk`, `uudid`) from `localStorage`.

### State Delta & Notification Transitions
- For each returned ticket (`newTicket`) in `res.data.data`:
  - Locates existing cached entry: `matchOldTicket = oldTickets.find(...)` matching `trainName` and `class`.
  - **Transition Condition 1 (Availability Increase)**:
    - If `matchOldTicket` exists and `newTicket.seats > matchOldTicket.seats`:
      - Plays notification audio: `notificationAudio.current.play()`
      - Displays toast: `newTicketToast(newTicket)`
  - **Transition Condition 2 (Initial Discovery)**:
    - If `!matchOldTicket`:
      - Appends `newTicket` to cached tickets.
      - Plays audio and displays toast.
  - **Transition Condition 3 (Depletion)**:
    - If a previously observed ticket is absent in `newTickets`, sets `oldTicket.seats = 0`.
- **Handoff Action**:
  - Each available ticket row renders a green "Purchase" button linking (`target="_blank"`) to `ticket.link`.

## 2. Server Pipeline & Upstream Shohoz Routing

### Route Architecture
```
Client POST /api/v1/tickets
  │
  ├──► express app.use('/api/v1', router)  [src/app.ts]
  │
  ├──► router.use('/tickets', TicketRoutes) [src/app/routes/index.ts]
  │
  ├──► router.post('/', validateRequest, TicketControllers.searchTickets) [ticket.route.ts]
  │
  ├──► TicketControllers.searchTickets [ticket.controller.ts]
  │     Extracts: token (from Authorization Bearer), ssdk, uudid, x-requested-with
  │
  ├──► TicketServices.searchTickets [ticket.service.ts]
  │     Validates presence of all 4 auth credentials (throws 401 if missing)
  │     Formats station names and dates for Shohoz API
  │
  ├──► GET https://railspaapi.shohoz.com/v1.0/web/bookings/search-trips-v2?from_city=...&to_city=...&date_of_journey=...&seat_class=S_CHAIR
  │     Passes upstream headers:
  │       Authorization: Bearer <token>
  │       x-device-key: <ssdk>
  │       x-device-id: <uudid>
  │       x-requested-with: XMLHttpRequest
  │
  └──► Response Normalization:
        Computes 15% VAT on AC/Berth/First classes
        Generates official railway booking link:
        https://eticket.railway.gov.bd/booking/train/search?fromcity=...&tocity=...&doj=...&class=...
```

## 3. Booking Link Format Specification
The booking link generated by the server has the structure:
```
https://eticket.railway.gov.bd/booking/train/search?fromcity={fromCity}&tocity={toCity}&doj={date}&class={seatClass}
```
Example:
```
https://eticket.railway.gov.bd/booking/train/search?fromcity=Dhaka&tocity=Khulna&doj=09-Jun-2025&class=AC_S
```
When this URL is opened in a logged-in browser, the Bangladesh Railway portal loads the train results for that route, date, and seat class. Clicking on the train expands the coaches and displays the interactive SVG/DOM seat map.
