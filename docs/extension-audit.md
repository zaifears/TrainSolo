# Extension and Token Synchronization Security & Architecture Audit

**Audited Target**: `train-ticket-tracker-sync-extension`, `train-ticket-tracker-client`, `train-ticket-tracker-server`  
**Date**: October 2026  
**Auditor**: Antigravity Assistant (for Md Al Shahoriar Hossain)

---

## 1. Executive Summary

This audit verifies the exact source code, permissions, storage mechanisms, and transit path of authentication tokens across the Bangladesh Railway ticket tracker ecosystem. The extension bridges authentication credentials from the official railway portal (`eticket.railway.gov.bd`) into the tracker web client (`train-ticket-tracker-bd.vercel.app`), which in turn passes them through the proxy server (`train-ticket-tracker-server`) to the upstream Shohoz API (`railspaapi.shohoz.com`).

## 2. Line-by-Line Extension Manifest & Script Audit

### 2.1 Manifest Analysis (`manifest.json`)
```json
{
    "manifest_version": 3,
    "name": "Train Ticket Tracker Sync",
    "version": "1.0.0",
    "description": "Sync token between BD train sites",
    "permissions": ["storage", "scripting", "tabs"],
    "host_permissions": [
        "https://eticket.railway.gov.bd/*",
        "https://train-ticket-tracker-bd.vercel.app/*"
    ],
    "action": {
        "default_popup": "popup.html",
        "default_title": "Train Ticket Tracker Sync"
    },
    "icons": {
        "16": "icon.png", "32": "icon.png", "48": "icon.png", "128": "icon.png"
    }
}
```

- **Manifest Version**: Manifest V3 (MV3 compliant).
- **Declared Permissions**:
  - `storage`: Enables `chrome.storage.local` to temporarily store extracted tokens.
  - `scripting`: Enables programmatic injection via `chrome.scripting.executeScript`.
  - `tabs`: Allows querying open tabs to locate matching origins.
- **Host Permissions**:
  - `https://eticket.railway.gov.bd/*`: Grants script injection and access into the official railway portal.
  - `https://train-ticket-tracker-bd.vercel.app/*`: Grants script injection into the hosted production client.
  - *Critical Note for Local Development*: Local URLs (e.g. `http://localhost:5173/*` or `http://localhost:4173/*`) are **not** present in `host_permissions`. For local development testing, `http://localhost:*/*` or `http://127.0.0.1:*/*` must be added to `host_permissions`.
- **Content Scripts**: None declared declaratively. All injection is done on-demand through `popup.js`.
- **Web Accessible Resources**: None declared.

### 2.2 Token Extraction Script (`sync.js`)
```javascript
(function () {
    const token = localStorage.getItem("token");
    const ssdk = localStorage.getItem("ssdk");
    const uudid = localStorage.getItem("uudid");

    if (token || ssdk || uudid) {
        chrome.storage.local.set(
            {
                bdTrainToken: token || null,
                bdTrainSSDK: ssdk || null,
                bdTrainUUDID: uudid || null,
            },
            () => { }
        );
    }
})();
```

- **Execution Context**: Executed in the DOM/page context of the railway tab (`eticket.railway.gov.bd`).
- **Source Keys (`window.localStorage`)**:
  - `token`: JWT or railway session bearer token.
  - `ssdk`: Shohoz device/session key.
  - `uudid`: Unique user device ID generated by the railway frontend.
- **Destination Keys (`chrome.storage.local`)**:
  - `bdTrainToken`: `token` (or `null`)
  - `bdTrainSSDK`: `ssdk` (or `null`)
  - `bdTrainUUDID`: `uudid` (or `null`)
- **Transformation**: Plaintext assignment, no hashing or encryption applied.

### 2.3 Extension Workflow & Ingestion (`popup.js`)
1. **User Action**: User clicks the "Sync Account" button (`#syncBtn`).
2. **Step 1 - Railway Tab Query**:
   - Queries open tabs for `*://eticket.railway.gov.bd/*`.
   - If not found, renders a "Visit eticket" button calling `chrome.tabs.create`.
   - If found, injects `sync.js` into `eticketTab.id`.
3. **Step 2 - Tracker Tab Query & Injection**:
   - Queries open tabs for `*://train-ticket-tracker-bd.vercel.app/*`.
   - If not found, prompts user with a "Visit tracker" button.
   - If found, executes an inline function in the tracker tab:
     - Retrieves `bdTrainToken`, `bdTrainSSDK`, `bdTrainUUDID` from `chrome.storage.local`.
     - Writes to tracker page's `localStorage`:
       - `localStorage.setItem("token", token)`
       - `localStorage.setItem("ssdk", ssdk)`
       - `localStorage.setItem("uudid", uudid)`
     - Sends runtime message `NO_TOKEN_FOUND` if `token` is missing.
4. **Step 3 - Client Navigation**:
   - Injects a navigation helper:
     - If pathname is `/login` or `/login-advanced`, navigates to `/`.
     - If pathname is `/`, reloads the page to trigger state re-initialization.

## 3. Client & Server Consumption Path

### 3.1 Client Interceptor (`train-ticket-tracker-client/src/helpers/axiosInstance.ts`)
```typescript
axiosInstance.interceptors.request.use(
    function (config) {
        const token = getFromLocalStorage('token');
        const ssdk = getFromLocalStorage('ssdk');
        const uudid = getFromLocalStorage('uudid');

        config.headers['x-requested-with'] = 'XMLHttpRequest';

        if (token) {
            config.headers.Authorization = `Bearer ${token}`;
        }
        if (uudid) {
            config.headers['x-device-id'] = uudid;
        }
        if (ssdk) {
            config.headers['x-device-key'] = ssdk;
        }

        return config;
    },
    ...
);
```
- The client reads credentials from its local storage.
- All requests sent to the backend proxy include:
  - `Authorization: Bearer <token>`
  - `x-device-id: <uudid>`
  - `x-device-key: <ssdk>`
  - `x-requested-with: XMLHttpRequest`

### 3.2 Server Proxy Pipeline (`train-ticket-tracker-server`)
1. **Controller (`ticket.controller.ts`)**:
   - Extracts:
     - `token`: Extracted from `req.headers.authorization` via `getTokenFromTokenBearer` (strips `Bearer ` prefix).
     - `ssdk`: `req.headers['x-device-key']`.
     - `uudid`: `req.headers['x-device-id']`.
     - `xRequestedWith`: `req.headers['x-requested-with']`.
2. **Service (`ticket.service.ts`)**:
   - Verifies that `token`, `ssdk`, `uudid`, and `xRequestedWith` are present. If any is missing, throws `ApiError(401, 'Unauthorized access')`.
   - Calls upstream Shohoz API:
     - Endpoint: `GET https://railspaapi.shohoz.com/v1.0/web/bookings/search-trips-v2?from_city=...&to_city=...&date_of_journey=...&seat_class=S_CHAIR`
     - Upstream Headers:
       - `Authorization: Bearer ${token}`
       - `x-device-key: ssdk`
       - `x-device-id: uudid`
       - `x-requested-with: xRequestedWith`
3. **Response Normalization**:
   - Maps each train and class seat inventory into `ITicket` items.
   - Computes fare (with 15% VAT calculation for AC/First classes).
   - Generates official booking link:  
     `https://eticket.railway.gov.bd/booking/train/search?fromcity=${fromCity}&tocity=${toCity}&doj=${date}&class=${seatClass}`.

## 4. Multi-Tier Storage & Security Profile

| Storage Location | Keys Stored | Scope / Lifetime | Security Risk Profile |
| :--- | :--- | :--- | :--- |
| **Railway Page `localStorage`** | `token`, `ssdk`, `uudid` | Domain `eticket.railway.gov.bd`, 24hr session | Origin-isolated. Subject to XSS if railway domain is compromised. |
| **`chrome.storage.local`** | `bdTrainToken`, `bdTrainSSDK`, `bdTrainUUDID` | Internal extension sandbox | Accessible only to this extension. Cleared only if overwritten or extension data is wiped. |
| **Tracker Page `localStorage`** | `token`, `ssdk`, `uudid` | Domain `train-ticket-tracker-bd.vercel.app` (or local origin) | Origin-isolated. Plaintext in browser profile. Cleared on logout or browser cache clear. |
| **Server Memory / Network Transit** | Request headers | Transient per HTTP request | Plaintext over TLS. Must **never** be logged in server stdout or error logs. |

## 5. Identified Gaps and Hardening Recommendations

1. **Local Development Host Permissions**:
   - Current extension only matches `https://train-ticket-tracker-bd.vercel.app/*`.
   - **Recommendation**: Add `http://localhost:*/*` and `http://127.0.0.1:*/*` to `manifest.json` and adjust query matching in `popup.js` to allow testing against local development client.
2. **Token Hygiene & Cleanup**:
   - `chrome.storage.local` retains the token indefinitely until re-sync.
   - **Recommendation**: Implement a clear-credentials button or automatic time-to-live (TTL) expiration in the extension popup.
3. **Server-Side Log Redaction**:
   - Ensure logger middlewares redact `req.headers.authorization`, `x-device-key`, and `x-device-id`.
4. **Boundary Isolation with Seat Selector**:
   - The local Playwright seat selector should NOT require token injection through the server; it directly connects to the user's already-logged-in browser profile via CDP (`http://127.0.0.1:9222`), preserving total session isolation.
